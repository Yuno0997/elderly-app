Create a high-fidelity web application UI screen for our thesis project called “SafeAlert Band,” an IoT-based elderly monitoring system with role-based access for Admin, Caregiver, and Relative. The new feature to design is an “Individual Resident Report” module, where a specific patient/resident has a dedicated report page that can be viewed, exported as PDF, and printed for family members, relatives, caregivers, or administrators.

IMPORTANT DESIGN DIRECTION:
Preserve the existing SafeAlert Band visual identity and interface style. The UI must look clean, professional, modern, healthcare-oriented, and thesis-appropriate. Use a conservative dashboard design with a slate, white, and soft neutral palette. Use semantic colors only:
- green for stable / normal
- yellow for warning
- red for critical
- gray for offline / inactive
Use blue-to-teal gradient very sparingly only for brand accents or page headers.
The layout must feel consistent with the rest of the SafeAlert Band system and must not look like a different product.

SCREEN TO DESIGN:
Create a desktop web application page for:
“Resident Profile > Reports”
This is a new tab within the resident detailed profile panel/page.

MAIN PURPOSE OF THE SCREEN:
This page allows an Admin, Caregiver, or Relative to generate, preview, export, and print an individual resident report. The report should be formal, readable, organized, and suitable for documentation purposes. It should support family requests for a patient’s health and incident records.

PAGE STRUCTURE:
1. Top header area
- Page title: “Individual Resident Report”
- Subtitle: “Generate printable and exportable health, monitoring, medication, and incident reports for this resident.”
- Breadcrumb: Dashboard / Residents / Resident Profile / Reports
- Include a resident status badge on the upper area such as Stable, Warning, Critical, or Offline
- Add a small timestamp like “Last updated: April 2026”

2. Resident summary card at the top
Display a clean profile summary card containing:
- resident photo/avatar
- full name
- age
- sex
- room/bed number
- assigned caregiver
- emergency contact / relative
- device ID / band ID
- latest health status
- last sync / last monitoring timestamp
This card should feel neat and professional, not overcrowded.

3. Report filter and generation controls
Add a control panel or filter bar with:
- date range selector
- report type dropdown
- quick filters: Daily, Weekly, Monthly, Custom Range
- report category checkboxes or toggles:
  - Health Monitoring Summary
  - Incident History
  - Medication Logs
  - Caregiver Notes
  - Sleep Anomaly Records
  - Unusual Pulse Records
- action buttons:
  - Generate Report
  - Export PDF
  - Print Report
  - Download CSV
Buttons should be aligned clearly and should look functional but elegant.

4. Report preview panel
This is the main body of the page.
Design a report preview container that looks printable and document-friendly.
The report should be divided into professional sections:

SECTION A: Patient / Resident Information
- Full Name
- Age
- Sex
- Room / Bed Number
- Assigned Caregiver
- Relative / Guardian Name
- Contact Information
- Device ID / Band ID

SECTION B: Health Monitoring Summary
- average heart rate
- highest pulse detected
- lowest pulse detected
- latest pulse reading
- latest monitoring status
- number of unusual pulse alerts
- sleep duration summary
- sleep anomaly count
- general remarks or condition summary

SECTION C: Incident History
- total fall incidents
- critical fall incidents
- date and time of each event
- severity level
- acknowledged by
- resolved by
- response duration
- notes / intervention performed
Display this in a clean table or incident list format.

SECTION D: Medication and Care Logs
- medication schedule given
- medications completed
- missed medications
- caregiver task logs
- care notes
- check-up observations

SECTION E: Trends and Analytics
Include small, clean healthcare-style data visualizations:
- pulse trend line chart
- incident count bar chart
- sleep anomaly frequency chart
- summary cards for totals
Charts must be minimal, readable, and consistent with the overall UI. Do not make them too colorful or flashy.

SECTION F: Report Footer
- report generated by
- generated date and time
- resident ID
- signature placeholder or “Reviewed by”
- a note such as “This report is system-generated by SafeAlert Band”
This footer should reinforce that the report is printable and formal.

5. Right-side quick action panel or floating utility area
Add a slim side utility section with:
- quick export options
- report history
- previous generated reports
- family request logs or request history
- share/send option placeholder for future enhancement
Keep this optional but well integrated if space allows.

ROLE-BASED BEHAVIOR TO REFLECT IN DESIGN:
- Admin: full access to generate, export, print, and view all report sections
- Caregiver: can generate and print reports only for assigned residents
- Relative: read-only report view with allowed download/print access only
Visually imply access control subtly through badges, labels, or interface hierarchy, but do not make the page cluttered.

DESIGN STYLE:
- clean healthcare dashboard
- modern admin panel
- professional and structured
- soft shadows
- rounded corners
- organized spacing
- strong information hierarchy
- readable typography
- emphasis on clarity and documentation
The report preview should feel like both a dashboard component and a printable document.

DO NOT:
- do not make the design overly colorful
- do not use playful or childish UI
- do not overcrowd cards with too much text
- do not make it look like a generic finance dashboard
- do not break the current SafeAlert Band branding and layout style

EXTRA DETAILS TO INCLUDE:
- Add a visible “Printable Report Preview” label
- Add a “Selected report period” field
- Add a tiny legend for incident severity if needed
- Add subtle icons for health, incidents, medications, and notes
- Include realistic placeholder patient data
- Make the layout presentation-ready for thesis defense
- Make it believable as a real system module for an elderly care monitoring platform

OUTPUT EXPECTATION:
Generate a complete, polished desktop web UI mockup for the Individual Resident Report module of SafeAlert Band, suitable for thesis presentation, system demonstration, and future implementation in Figma or frontend development.
